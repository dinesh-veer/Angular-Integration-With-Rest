Architecture & Design Patterns

Understand how Angular REST Integration is structured, how standalone components work, and how asynchronous change detection guarantees responsive view updates.

Overview

The project follows Angular's single-responsibility design principles, decoupling data retrieval, state management, and UI rendering into distinct layers: 

┌────────────────────────────────────────────────────────┐
│                      UI View                           │
│   (app.component.html - *ngIf, *ngFor, [innerHTML])    │
└───────────────────────────▲────────────────────────────┘
                            │ (Template Bindings)
┌───────────────────────────┴────────────────────────────┐
│                  Component Controller                  │
│   (AppComponent - State, Events, ChangeDetectorRef)    │
└───────────────────────────▲────────────────────────────┘
                            │ (RxJS Observable Stream)
┌───────────────────────────┴────────────────────────────┐
│                      Service Layer                     │
│   (AppServiceService - HttpClient, REST URL, map())    │
└───────────────────────────▲────────────────────────────┘
                            │ (HTTP GET Request)
┌───────────────────────────┴────────────────────────────┐
│               External REST API Server                 │
│   (WordPress Public REST API v1.1)                     │
└────────────────────────────────────────────────────────┘

Layered Architecture

1. Service Layer (AppServiceService)

The service is decorated with @Injectable({ providedIn: 'root' }), making it a singleton accessible application-wide. It injects Angular's modern HttpClient and provides methods that return strongly typed RxJS Observable instances.

2. Component Controller (AppComponent)

Implemented as a standalone component using standalone: true. It subscribes to the service observable in its ngOnInit lifecycle hook, stores received items in local state, and manages user interactions (such as post clicks).

3. Presentation Layer (app.component.html)

Uses declarative directives (*ngIf for loading states, *ngFor for listing items, and [innerHTML] for rendering WordPress post titles and HTML articles).

Standalone Component Pattern

Traditional Angular projects required every component to be declared inside an NgModule (typically AppModule). Modern Angular replaces this with Standalone Components: 

// main.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { AppComponent } from './app/app.component';

bootstrapApplication(AppComponent, appConfig)
  .catch((err) => console.error(err));

Dependencies are imported directly into the component decorator via imports: [CommonModule]. Global providers such as provideHttpClient() and provideZoneChangeDetection() are supplied in appConfig (an ApplicationConfig object).

Change Detection Flow

When data is fetched asynchronously over the network, Angular must be informed that the component state has changed so it can re-render the template: 

1. HTTP Request Triggered
   appService.getAll() initiates GET request via HttpClient

2. Asynchronous Delay (~1 second)
   Network roundtrip to WordPress API endpoint

3. Observable Emits Data
   subscribe({ next: (restItems) => { ... } }) callback executes

4. State Mutation & Change Notification
   this.restItems = restItems;
   this.cdr.markForCheck(); // Explicitly schedules change detection pass

5. Zone.js / Scheduler Tick
   Angular reconciles the virtual DOM with the real DOM

6. UI Updates
   "Loading ....." div disappears, post list renders instantly

By combining zone.js with explicit this.cdr.markForCheck(), the component functions reliably in both traditional zone-based execution and modern zoneless Angular environments.

Legacy vs. Modern Angular Architecture

Concept Traditional Angular (v6) Modern Angular (v21)
Module Boundary Mandatory @NgModule({ declarations: [...] }) standalone: true directly imports dependencies
HTTP Setup HttpClientModule in imports: [...] provideHttpClient() in ApplicationConfig
Change Detection Unconfigurable Zone.js monkey patching Configurable Zone.js with coalescing / Zoneless ready
